# RepoGuard v0.7: First Real Gemma Baseline

v0.7 moves RepoGuard from infrastructure building into measured model execution.

## Official baseline model

Use:

```text
google/gemma-4-12B
```

The official model card lists the checkpoint at roughly 24 GB and demonstrates
loading it with `AutoProcessor` and `AutoModelForMultimodalLM`.

## Safety model

Normal RepoGuard operation still uses manual approval.

For benchmark runs only, v0.7 supports:

```text
approval_policy = auto_low_risk
```

This is paired with repository isolation. Every benchmark task is copied into a
temporary directory before the agent runs. Low-risk edits can therefore be
applied and tested without modifying the source benchmark fixtures.

High-risk paths remain subject to the governance controls.

## Cloud GPU setup

A GPU runtime is recommended for the real Gemma 4 12B baseline.

Install:

```bash
git clone https://github.com/faithfulord1/palm92-repoguard.git
cd palm92-repoguard
python -m pip install -U pip
python -m pip install -e ".[gemma,dev]"
```

Run preflight:

```bash
python scripts/v0_7_preflight.py
```

Run the first measured baseline:

```bash
python scripts/run_v0_7_baseline.py
```

## Evidence generated

The run writes:

```text
artifacts/v0.7/baseline-v001.jsonl
artifacts/v0.7/baseline-v001-summary.json
```

Do not manually edit these files after the run. Preserve them as raw experiment
evidence.

## Baseline question

The baseline answers:

> How well does the un-post-trained Gemma 4 12B checkpoint perform on the
> controlled RepoGuard software-repair task pack when given the basic tool loop?

Later experiments will hold the task pack constant while changing one component
at a time.
