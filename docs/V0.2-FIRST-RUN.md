# RepoGuard v0.2: First Agent Run

## Zero-download smoke test

From the project root:

```bash
python -m pip install -e .
repoguard examples/buggy_repo "The divide function returns the wrong result" --backend mock
```

This verifies:
- repository discovery,
- model adapter boundary,
- investigation orchestration,
- governance decision,
- JSON audit generation.

## Gemma 4 run

Install the optional model dependencies:

```bash
python -m pip install -e ".[gemma]"
```

Then run:

```bash
repoguard examples/buggy_repo "The divide function returns the wrong result" \
  --backend gemma \
  --model-id google/gemma-4-12B-it
```

The model is intentionally configurable so experiments can compare Gemma 4
variants or fine-tuned checkpoints without changing the core agent.

## v0.2 success criterion

RepoGuard must:
1. enumerate the demo repository,
2. produce an investigation plan,
3. record evidence in an audit JSON file,
4. trigger a human gate when sensitive paths are present.

Actual autonomous file reading, patch generation and iterative test repair belong
to v0.3.
