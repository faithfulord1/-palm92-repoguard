# RepoGuard v0.4: Human Approval and Experiment Evidence

## What changed

RepoGuard now stages model-proposed edits instead of silently applying them.

Every proposed edit produces:

- a proposal ID,
- the target path,
- a reason,
- a unified diff preview,
- a risk classification,
- a pending approval state.

A human can explicitly approve or reject a proposal.

## Approval flow

1. The model investigates the issue.
2. The model proposes a complete file replacement.
3. RepoGuard generates a diff and records the proposal.
4. No file is changed yet.
5. A human reviews the diff.
6. Approve applies the change.
7. Reject preserves the original file.
8. The audit ledger records the decision.

## Competition experiment logger

The new JSONL logger records one structured row per run, including:

- experiment ID,
- task ID,
- model and variant,
- prompt version,
- final status,
- test outcome,
- number of steps,
- files touched,
- proposals created,
- approvals and rejections,
- whether human intervention was required,
- latency,
- timestamp,
- optional metadata.

This becomes the evidence base for the Kaggle paper and ablation studies.
