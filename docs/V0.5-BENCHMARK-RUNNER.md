# RepoGuard v0.5: Competition Benchmark Runner

RepoGuard can now run repeatable benchmark suites and save one structured
experiment record per task.

## New benchmark flow

Task set → Model configuration → RepoGuard repair run → Metrics capture →
JSONL evidence log → Aggregate summary

## Captured metrics

Per task:

- experiment ID
- task ID
- model ID
- model variant
- prompt version
- final status
- tests passed
- steps used
- files touched
- proposals created
- approvals / rejections
- human intervention required
- latency
- task metadata

Suite summary:

- fix rate
- test-pass rate
- average steps
- average latency
- human-intervention rate
- proposal totals

## Example

```bash
repoguard-benchmark benchmarks/demo_tasks.json \
  --backend gemma \
  --model-id google/gemma-4-12B-it \
  --experiment-id tools-v001 \
  --variant base
```

Outputs:

```text
artifacts/benchmark-runs.jsonl
artifacts/benchmark-summary.json
```

## Competition experiment matrix

Recommended sequence:

1. baseline-v001
2. tools-v001
3. planning-v001
4. verification-v001
5. governance-v001
6. full-repoguard-v001

Use the same task set across all configurations. This turns our architecture
choices into measurable ablation experiments for the Kaggle paper.
